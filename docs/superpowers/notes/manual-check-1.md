# 1차 DOM 수동 검증 (Task 2~6)

서브에이전트가 확인할 수 없는 항목들이다. Node 테스트(라벨 생성, 기하·스타일 필터, 화면 순서 정렬)는 전부 통과한 상태이므로, 여기서는 **DOM에서만 드러나는 것**만 본다.

## 준비

1. Claude Desktop에서 `Cmd+Alt+I` → Console 탭
2. `src/hintvim.js` **전체 내용**을 붙여넣고 Enter
3. 콘솔에 `[hintvim] ready`가 찍히는지 확인

설치는 아직 하지 않는다. 콘솔 실행만으로 전부 확인된다. 지우려면 `Cmd+R`.

## A. 재실행 안전성 (Task 2)

| # | 확인 | 기대 |
|---|---|---|
| A1 | 같은 코드를 한 번 더 붙여넣기 | `ready`가 두 번째로 찍히고, 에러 없음 |
| A2 | `window.__hintvim.teardown` 입력 | 함수가 나온다 |

## B. 힌트 대상 탐색 (Task 4)

콘솔에서:

```javascript
window.__hintvim.collectTargets().length
```

| # | 확인 | 기대 |
|---|---|---|
| B1 | 위 명령 | 0보다 큰 수 |
| B2 | 아래 명령으로 육안 확인 | 실제 버튼·링크에 테두리가 생긴다. 큰 컨테이너 하나가 통째로 잡히지 않는다 |

```javascript
window.__hintvim.collectTargets().forEach(el => el.style.outline = '2px solid lime')
```

확인 후 `Cmd+R`로 리로드하고, 코드를 다시 붙여넣는다.

## C. 오버레이 (Task 5)

**콘솔이 아니라 앱 창을 클릭해 포커스를 옮긴 뒤** 진행한다.

| # | 확인 | 기대 |
|---|---|---|
| C1 | `Ctrl+;` | 클릭 가능한 요소마다 노란 라벨이 뜬다 |
| C2 | 라벨 겹침 | 읽을 수 없게 겹친 라벨이 없다 |
| C3 | 힌트가 뜬 채로 대화창 스크롤 | 라벨이 요소를 따라 움직인다. 원래 자리에 남지 않는다 |
| C4 | 창 크기 변경 | 라벨이 새 위치로 따라간다 |
| C5 | 라벨이 붙는 위치 | 대상 요소에서 너무 멀리 떨어진 라벨이 없다 |

## D. 키 처리와 실행 (Task 6)

| # | 확인 | 기대 |
|---|---|---|
| D1 | `Ctrl+;` 후 라벨 첫 글자 입력 | 매칭 안 되는 라벨이 사라진다 |
| D2 | `Backspace` | 사라졌던 라벨이 돌아온다 |
| D3 | 라벨 완성 (버튼 대상) | 그 버튼이 눌리고 힌트가 사라진다 |
| D4 | 라벨 완성 (입력창 대상) | 커서가 입력창에 들어간다. 클릭이 아니라 포커스 |
| D5 | 라벨에 없는 글자 입력 | 오버레이가 짧게 흔들리고 모드는 유지된다 |
| D6 | `Esc` | 힌트가 사라진다 |
| D7 | 힌트 없는 상태에서 평소처럼 타이핑 | 아무것도 가로채지 않는다 |

## E. 한글 입력 (Task 6, 가장 중요)

이게 깨지면 확장을 쓸 수 없다.

| # | 확인 | 기대 |
|---|---|---|
| E1 | 입력창에 한글 문장 타이핑 | 정상 입력. 글자가 깨지거나 힌트가 뜨지 않는다 |
| E2 | 한글 조합 도중(예: `ㄱ` 상태에서) `Ctrl+;` | 조합이 깨지지 않는다 |
| E3 | 힌트를 띄운 뒤 `Esc`로 닫고 한글 입력 | 정상 입력 |

## F. 미해결 항목 확인

여기 두 개는 **결과를 알려주시면** 제가 판단합니다.

| # | 확인 | 무엇을 보나 |
|---|---|---|
| F1 | 힌트가 뜬 상태에서 텍스트를 선택하고 `Cmd+C` | 복사가 되는지, 아니면 힌트 `c`가 눌린 것처럼 동작하는지. Vimium과 같으면 후자가 정상입니다 |
| F2 | 코드 블록이 길어 가로 스크롤이 생기는 대화에서 힌트를 띄우고 스크롤 | 라벨이 따라오는지. 파일 뷰어는 내부적으로 Shadow DOM을 쓰는 곳이 있어 여기만 별도 확인이 필요합니다 |
