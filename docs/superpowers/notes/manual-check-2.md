# 2차 DOM 수동 검증 (Task 7~9)

1차 검증 이후 추가된 것: 스크롤 커맨드, 설정 저장·검증·설정 화면, 도움말 오버레이.

## 준비

```bash
pbcopy < /Users/dev-soon/workspace/project/claude-vimium/src/claude-vimium.js
```

Claude Desktop에서 `Cmd+Alt+I` → Console → `Cmd+V` → Enter. **그다음 앱 창을 클릭해 포커스를 옮긴다.** 지우려면 `Cmd+R`.

## A. 스크롤 (Task 7)

`Ctrl+;`로 힌트를 띄운 상태에서 확인한다.

| # | 키 | 기대 |
|---|---|---|
| A1 | `j` / `k` | 대화가 아래/위로 스크롤되고 라벨이 따라 움직인다 |
| A2 | `↓` / `↑` | 같음 |
| A3 | `Ctrl+d` / `Ctrl+u` | 반 페이지씩 이동 |
| A4 | `Home` / `End` | 대화 맨 위 / 맨 아래 |
| A5 | 스크롤한 뒤 라벨 완성 | 올바른 요소가 눌린다 (라벨이 밀린 뒤에도 매칭이 맞는지) |
| A6 | **한글 자판으로** `j` / `k` | 영문 자판과 똑같이 스크롤된다 |
| A7 | 코드 블록이 있는 대화에서 `h` / `l` | 가로 스크롤이 있으면 좌우 이동 |

A6이 핵심입니다. 1차 검증에서 라벨 입력이 한글 자판에서 안 되던 것과 같은 원인이 스크롤 키에도 있었고, 그래서 Task 7에서 키 해석을 공통으로 뽑았습니다.

## B. 설정 화면 (Task 8)

| # | 확인 | 기대 |
|---|---|---|
| B1 | `Ctrl+;` → `,` | 설정 패널이 열리고 힌트는 사라진다 |
| B2 | 리더 키 버튼 클릭 → `Ctrl+'` | 버튼 라벨이 `Ctrl+'`로 바뀐다 |
| B3 | 문자셋에 `hjkl` 입력 후 저장 | 저장 거부 + `'h' 는 이동/명령 키로 예약되어 있습니다` |
| B4 | 문자셋에 `aab` 입력 후 저장 | `중복된 문자가 있습니다` |
| B5 | 스크롤 양에 `0` 입력 후 저장 | 거부 |
| B6 | 유효한 값으로 저장 | 패널이 닫히고 토스트가 뜬다 |
| B7 | 바꾼 리더 키로 힌트 호출 | 새 키로 동작한다 |
| B8 | `Cmd+R` 리로드 후 코드 재실행 | 바꾼 설정이 유지된다 |
| B9 | 패널에서 `Esc` | 패널만 닫힌다 |

### B10 — 리더 키 함정 방지 (이번에 고친 것)

| 순서 | 동작 | 기대 |
|---|---|---|
| 1 | 리더 키 버튼 클릭 (`키를 누르세요…` 상태) | — |
| 2 | 키를 누르지 말고 패널 바깥을 클릭해 닫기 | 패널이 닫힌다 |
| 3 | 아무 키나 누르기 (예: `a`) | **리더 키가 바뀌지 않아야 한다** |
| 4 | `Ctrl+;` | 여전히 원래 리더 키로 힌트가 뜬다 |

3번에서 리더 키가 `a`로 바뀌면 리스너 누수가 안 막힌 겁니다.

### B11 — 맨 문자 리더 키 거부 (이번에 고친 것)

| 순서 | 동작 | 기대 |
|---|---|---|
| 1 | 리더 키 버튼 클릭 후 **모디파이어 없이** `h` 누르기 | 버튼에 `h`로 표시됨 |
| 2 | 저장 | **거부** + `리더 키에는 Ctrl, Alt, Cmd 중 하나가 필요합니다` |

이게 통과 못 하면 심각합니다. 맨 문자를 리더 키로 저장하면 `h`를 칠 때마다 힌트가 뜨고, 설정 화면은 그 힌트 모드를 통해서만 열려서 되돌릴 방법이 앱 안에 없습니다.

## C. 도움말 (Task 9)

| # | 확인 | 기대 |
|---|---|---|
| C1 | `Ctrl+;` → `?` | 키 바인딩 표가 열린다 |
| C2 | 표의 리더 키 행 | 기본값이 아니라 **현재 설정된** 키가 보인다 (B7에서 바꿨다면 그 키) |
| C3 | 표의 문자셋 행 | 현재 문자셋이 보인다 |
| C4 | `Esc` | 도움말이 닫힌다 |
